# 01-数据库表结构设计

## 1. 概述

本章设计 RBAC（Role-Based Access Control）权限模型的五张核心数据表。采用经典的五表结构，表之间通过逻辑关联而非物理外键，这是对标若依框架的标准做法。

**五张核心表**：

| 表名 | 说明 | 对标若依 |
| :--- | :--- | :--- |
| `sys_user` | 系统用户表 | sys_user |
| `sys_role` | 角色信息表 | sys_role |
| `sys_menu` | 菜单权限表 | sys_menu |
| `sys_user_role` | 用户角色关联表 | sys_user_role |
| `sys_role_menu` | 角色菜单关联表 | sys_role_menu |

**不使用物理外键的原因**：
1. 分库分表时物理外键会成为障碍
2. 数据量大时外键校验影响性能
3. 逻辑删除场景下外键约束难以处理

## 2. 建表 SQL

### 2.1 完整 SQL 脚本

在 MySQL 中执行以下 SQL 创建所有表。确保 Docker 容器中的 `barezen_oa` 数据库已创建。

```sql
-- ============================================
-- BareZen_OA RBAC 权限系统建表脚本
-- 执行方式：登录 MySQL 后逐条执行或一次性粘贴
-- ============================================

USE barezen_oa;

-- 1. 系统用户表
DROP TABLE IF EXISTS sys_user;
CREATE TABLE sys_user (
    id          BIGINT PRIMARY KEY COMMENT '主键ID（雪花算法）',
    user_name   VARCHAR(64)  NOT NULL UNIQUE COMMENT '登录用户名',
    nick_name   VARCHAR(64)  DEFAULT '' COMMENT '用户昵称',
    password    VARCHAR(128) NOT NULL COMMENT '密码（BCrypt加密）',
    email       VARCHAR(128) DEFAULT '' COMMENT '邮箱',
    phone       VARCHAR(20)  DEFAULT '' COMMENT '手机号',
    sex         CHAR(1)      DEFAULT '0' COMMENT '性别（0=未知 1=男 2=女）',
    avatar      VARCHAR(256) DEFAULT '' COMMENT '头像路径',
    status      CHAR(1)      DEFAULT '1' COMMENT '状态（0=停用 1=正常）',
    login_ip    VARCHAR(64)  DEFAULT '' COMMENT '最后登录IP',
    login_date  DATETIME     DEFAULT NULL COMMENT '最后登录时间',
    remark      VARCHAR(500) DEFAULT '' COMMENT '备注',
    create_time DATETIME     NOT NULL COMMENT '创建时间',
    update_time DATETIME     NOT NULL COMMENT '更新时间',
    create_by   BIGINT       DEFAULT NULL COMMENT '创建者ID',
    update_by   BIGINT       DEFAULT NULL COMMENT '更新者ID',
    del_flag    TINYINT      DEFAULT 0 COMMENT '逻辑删除（0=正常 1=已删除）',
    INDEX idx_user_name (user_name),
    INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='系统用户表';

-- 2. 角色信息表
DROP TABLE IF EXISTS sys_role;
CREATE TABLE sys_role (
    id          BIGINT PRIMARY KEY COMMENT '主键ID',
    role_name   VARCHAR(64)  NOT NULL COMMENT '角色名称（如：超级管理员）',
    role_key    VARCHAR(64)  NOT NULL UNIQUE COMMENT '角色标识（如：admin）',
    role_sort   INT          DEFAULT 0 COMMENT '排序号（越小越靠前）',
    status      CHAR(1)      DEFAULT '1' COMMENT '状态（0=停用 1=正常）',
    remark      VARCHAR(500) DEFAULT '' COMMENT '备注',
    create_time DATETIME     NOT NULL COMMENT '创建时间',
    update_time DATETIME     NOT NULL COMMENT '更新时间',
    create_by   BIGINT       DEFAULT NULL COMMENT '创建者ID',
    update_by   BIGINT       DEFAULT NULL COMMENT '更新者ID',
    del_flag    TINYINT      DEFAULT 0 COMMENT '逻辑删除',
    INDEX idx_role_key (role_key),
    INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='角色信息表';

-- 3. 菜单权限表
DROP TABLE IF EXISTS sys_menu;
CREATE TABLE sys_menu (
    id          BIGINT PRIMARY KEY COMMENT '主键ID',
    parent_id   BIGINT       DEFAULT 0 COMMENT '父菜单ID（0=顶级菜单）',
    menu_name   VARCHAR(64)  NOT NULL COMMENT '菜单名称',
    menu_type   CHAR(1)      NOT NULL COMMENT '菜单类型（M=目录 C=菜单 F=按钮）',
    perms       VARCHAR(128) DEFAULT '' COMMENT '权限标识（如：system:user:list）',
    path        VARCHAR(256) DEFAULT '' COMMENT '路由地址',
    component   VARCHAR(256) DEFAULT '' COMMENT '组件路径',
    icon        VARCHAR(64)  DEFAULT '#' COMMENT '菜单图标',
    order_num   INT          DEFAULT 0 COMMENT '排序号',
    visible     CHAR(1)      DEFAULT '1' COMMENT '是否可见（0=隐藏 1=显示）',
    status      CHAR(1)      DEFAULT '1' COMMENT '状态',
    remark      VARCHAR(500) DEFAULT '' COMMENT '备注',
    create_time DATETIME     NOT NULL COMMENT '创建时间',
    update_time DATETIME     NOT NULL COMMENT '更新时间',
    create_by   BIGINT       DEFAULT NULL COMMENT '创建者ID',
    update_by   BIGINT       DEFAULT NULL COMMENT '更新者ID',
    del_flag    TINYINT      DEFAULT 0 COMMENT '逻辑删除',
    INDEX idx_parent_id (parent_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='菜单权限表';

-- 4. 用户角色关联表
DROP TABLE IF EXISTS sys_user_role;
CREATE TABLE sys_user_role (
    user_id BIGINT NOT NULL COMMENT '用户ID',
    role_id BIGINT NOT NULL COMMENT '角色ID',
    PRIMARY KEY (user_id, role_id),
    INDEX idx_user_id (user_id),
    INDEX idx_role_id (role_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户角色关联表';

-- 5. 角色菜单关联表
DROP TABLE IF EXISTS sys_role_menu;
CREATE TABLE sys_role_menu (
    role_id BIGINT NOT NULL COMMENT '角色ID',
    menu_id BIGINT NOT NULL COMMENT '菜单ID',
    PRIMARY KEY (role_id, menu_id),
    INDEX idx_role_id (role_id),
    INDEX idx_menu_id (menu_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='角色菜单关联表';
```

### 2.2 ER 关系图

```text
sys_user (1) ----< sys_user_role >---- (1) sys_role (1) ----< sys_role_menu >---- (1) sys_menu
```

一个用户可以有多个角色，一个角色可以有多个菜单权限。

## 4. 字段说明

### sys_user 字段

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| user_name | varchar(64) | 登录用户名，唯一索引 |
| password | varchar(128) | BCrypt 加密后的密码 |
| status | char(1) | 0=停用 1=正常，被停用的用户无法登录 |
| login_ip | varchar(64) | 最后登录 IP，用于审计 |
| login_date | datetime | 最后登录时间 |

### sys_menu 字段

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| menu_type | char(1) | M=目录 C=菜单 F=按钮，前端据此渲染不同组件 |
| perms | varchar(128) | 权限标识，格式：模块:资源:操作，如 system:user:list |
| path | varchar(256) | Vue Router 的路由路径 |
| component | varchar(256) | Vue 组件路径（views/ 下的相对路径） |
| visible | char(1) | 0=侧边栏隐藏 1=显示 |

# 04-菜单权限模块

## 1. 功能概述

菜单权限模块管理系统的导航菜单和按钮级权限。菜单表（sys_menu）采用 parent_id 字段实现树形结构，通过 menu_type 区分三个层级：

| 类型 | 编码 | 说明 | 前端对应 | 是否创建路由 |
| :--- | :---: | :--- | :--- | :---: |
| 目录 | M | 侧边栏父级节点，可展开收起 | 嵌套路由（Layout） | 是 |
| 菜单 | C | 侧边栏叶子节点，点击跳转页面 | 页面路由 | 是 |
| 按钮 | F | 页面内的操作按钮，控制可见性 | 权限指令 v-permission | 否 |

**为什么需要按钮级权限？**

假设你有一个用户管理页面，超级管理员可以看到"新增"、"编辑"、"删除"按钮，而普通用户只能看到"查询"按钮。如果只在路由层面控制权限（能否访问 /system/user），那普通用户进入页面后仍然能看到所有按钮，只是点击后会收到错误提示。按钮级权限从 UI 层面直接隐藏按钮，用户体验更好。

**树形结构示例**：
```
系统管理 (M)  parent_id=0  path=/system
├── 用户管理 (C)  parent_id=1  path=user  component=system/user/index
│   ├── 查询用户 (F)  perms=system:user:list
│   ├── 新增用户 (F)  perms=system:user:add
│   ├── 修改用户 (F)  perms=system:user:edit
│   └── 删除用户 (F)  perms=system:user:delete
├── 角色管理 (C)  parent_id=1  path=role  component=system/role/index
│   ├── 查询角色 (F)  perms=system:role:list
│   ├── 新增角色 (F)  perms=system:role:add
│   └── 删除角色 (F)  perms=system:role:delete
└── 菜单管理 (C)  parent_id=1  path=menu  component=system/menu/index
    └── 查询菜单 (F)  perms=system:menu:list
```

## 2. 设计原理

### 2.1 三种菜单类型的详细区别

**目录（M）**：
- 在侧边栏显示为可展开/收起的菜单父项
- 对应的 component 通常是 Layout（框架布局组件）
- path 以 `/` 开头（如 `/system`）
- 点击时展开子菜单，不跳转页面
- 本身不设置 perms 字段

**菜单（C）**：
- 在侧边栏显示为叶子节点
- 对应具体的页面路由（如 `/system/user`）
- component 填写 Vue 组件路径（如 system/user/index）
- 需要设置 perms 字段
- 点击时跳转到对应页面

**按钮（F）**：
- 不在侧边栏显示
- 不参与路由导航
- perms 字段存放权限标识：`模块:资源:操作`
- 前端通过 `v-permission` 指令控制按钮显隐

### 2.2 权限标识命名规范

`perms` 字段遵循三段式命名：`模块:资源:操作`

| 示例 | 含义 | 位置 |
| :--- | :--- | :--- |
| `system:user:list` | 系统管理-用户-查询 | 查询用户按钮 |
| `system:user:add` | 系统管理-用户-新增 | 新增用户按钮 |
| `system:user:edit` | 系统管理-用户-修改 | 修改用户按钮 |
| `system:user:delete` | 系统管理-用户-删除 | 删除用户按钮 |
| `system:role:list` | 系统管理-角色-查询 | 查询角色按钮 |
| `monitor:online:list` | 监控-在线用户-查询 | 查询在线用户 |

### 2.3 parent_id 的树形结构

parent_id 为 0 表示顶级菜单。查询所有菜单后，需要在后端（或前端）组装为树形结构返回。

**为什么要在后端组装而非前端组装？**

| 方案 | 优点 | 缺点 |
| :--- | :--- | :--- |
| 后端组装 | 前端解耦，切换前端框架不受影响 | 增加服务端一次遍历开销 |
| 前端组装 | 后端简单，直接返回列表 | 前端需写递归逻辑，换框架需重写 |

本系统选择**后端组装**，对标若依框架的做法，保证数据结构的一致性。

**后端组装树形结构的代码**：

```java
/**
 * 将扁平的菜单列表转换为树形结构
 *
 * 输入：[{id:1,parentId:0,name:'系统管理'}, {id:2,parentId:1,name:'用户管理'}, ...]
 * 输出：[{id:1,parentId:0,name:'系统管理',children:[{id:2,parentId:1,name:'用户管理'},...]}]
 *
 * 时间复杂度：O(n²)（网上常见的递归写法）
 * 优化方案：使用 HashMap 缓存，可将复杂度降至 O(n)
 */
public List<SysMenu> buildMenuTree(List<SysMenu> menuList) {
    // 过滤掉按钮（F），只保留目录（M）和菜单（C）
    List<SysMenu> menuOnly = menuList.stream()
        .filter(m -> !"F".equals(m.getMenuType()))
        .collect(Collectors.toList());

    // 1. 找出所有顶级菜单（parentId == 0）
    List<SysMenu> tree = menuOnly.stream()
        .filter(m -> m.getParentId() == 0)
        .sorted(Comparator.comparingInt(SysMenu::getOrderNum))
        .collect(Collectors.toList());

    // 2. 为每个顶级菜单递归设置子菜单
    for (SysMenu menu : tree) {
        menu.setChildren(getChildren(menu, menuOnly));
    }
    return tree;
}

/**
 * 递归查找当前菜单的所有子菜单
 */
private List<SysMenu> getChildren(SysMenu parent, List<SysMenu> all) {
    return all.stream()
        .filter(m -> parent.getId().equals(m.getParentId()))
        .sorted(Comparator.comparingInt(SysMenu::getOrderNum))
        .peek(m -> m.setChildren(getChildren(m, all)))
        .collect(Collectors.toList());
}
```

### 2.4 根据角色查询权限

用户登录后，权限系统需要根据用户的角色查询对应的权限标识列表。核心 SQL：

```sql
-- 三表联查：角色 → 角色菜单关联表 → 菜单表
SELECT DISTINCT m.perms
FROM sys_menu m
LEFT JOIN sys_role_menu rm ON m.id = rm.menu_id
LEFT JOIN sys_user_role ur ON rm.role_id = ur.role_id
WHERE ur.user_id = #{userId}
  AND m.perms IS NOT NULL
  AND m.perms != ''
  AND m.del_flag = 0
```

查询结果示例：`["system:user:list", "system:user:add", "system:role:list", ...]`

## 5. 步骤二：创建 SysMenuMapper

### 5.1 SysMenuMapper.java

文件路径：`bz_framework_core/src/main/java/com/linan/system/mapper/SysMenuMapper.java`

```java
package com.linan.system.mapper;

import com.baomidou.mybatisplus.core.mapper.BaseMapper;
import com.linan.system.entity.SysMenu;
import org.apache.ibatis.annotations.Mapper;
import org.apache.ibatis.annotations.Param;
import org.apache.ibatis.annotations.Select;

import java.util.List;

/**
 * 菜单 Mapper 接口
 *
 * 除了继承 BaseMapper 的通用 CRUD 方法外，额外提供：
 * - selectPermsByRoleId：根据角色ID查询该角色拥有的权限标识列表
 * - selectMenusByUserId：根据用户ID查询所有可见菜单
 */
@Mapper
public interface SysMenuMapper extends BaseMapper<SysMenu> {

    /**
     * 根据角色ID查询权限标识列表
     *
     * 联表查询：sys_role_menu + sys_menu
     * 只提取 perms 不为空的记录（按钮权限）
     *
     * @param roleId 角色ID
     * @return 权限标识集合，如 ["system:user:list", "system:user:add"]
     */
    @Select("SELECT m.perms FROM sys_menu m " +
            "LEFT JOIN sys_role_menu rm ON m.id = rm.menu_id " +
            "WHERE rm.role_id = #{roleId} " +
            "AND m.perms IS NOT NULL AND m.perms != '' " +
            "AND m.del_flag = 0")
    List<String> selectPermsByRoleId(@Param("roleId") Long roleId);

    /**
     * 根据用户ID查询所有菜单（用于构建动态路由）
     *
     * 三表联查：sys_user_role + sys_role_menu + sys_menu
     * 只返回 M（目录）和 C（菜单）类型，不返回 F（按钮）
     *
     * @param userId 用户ID
     * @return 菜单列表（扁平结构，需后续组装为树形）
     */
    @Select("SELECT DISTINCT m.* FROM sys_menu m " +
            "LEFT JOIN sys_role_menu rm ON m.id = rm.menu_id " +
            "LEFT JOIN sys_user_role ur ON rm.role_id = ur.role_id " +
            "WHERE ur.user_id = #{userId} " +
            "AND m.menu_type IN ('M', 'C') " +
            "AND m.status = '1' " +
            "AND m.del_flag = 0 " +
            "ORDER BY m.order_num ASC")
    List<SysMenu> selectMenusByUserId(@Param("userId") Long userId);
}
```

**逐行讲解**：

- `selectPermsByRoleId`：只查询 perms 不为空的菜单（即按钮权限）。目录和菜单不需要 perms，它们在路由层面控制。
- `selectMenusByUserId`：只查询 M 和 C 类型（目录和菜单），返回给前端构建侧边栏和路由。F 类型（按钮）不参与导航。
- `DISTINCT`：三表联查可能产生重复记录，使用 DISTINCT 去重。
- `ORDER BY m.order_num ASC`：按排序号升序排列，保证菜单顺序可控。

### 6.2 SysMenuServiceImpl.java

文件路径：`bz_framework_core/src/main/java/com/linan/system/service/impl/SysMenuServiceImpl.java`

```java
package com.linan.system.service.impl;

import com.baomidou.mybatisplus.extension.service.impl.ServiceImpl;
import com.linan.system.entity.SysMenu;
import com.linan.system.mapper.SysMenuMapper;
import com.linan.system.service.ISysMenuService;
import org.springframework.stereotype.Service;
import java.util.Comparator;
import java.util.List;
import java.util.stream.Collectors;

@Service
public class SysMenuServiceImpl
        extends ServiceImpl<SysMenuMapper, SysMenu>
        implements ISysMenuService {

    /**
     * 构建用户菜单树
     *
     * 1. 根据用户ID从数据库查询所有可访问的菜单（M + C）
     * 2. 将扁平列表组装为树形结构
     * 3. 返回顶层菜单（parentId=0）的列表
     */
    @Override
    public List<SysMenu> buildMenuTreeByUserId(Long userId) {
        // 1. 查询原始菜单列表（扁平）
        List<SysMenu> menuList = baseMapper.selectMenusByUserId(userId);

        // 2. 组装树形结构
        return buildTree(menuList);
    }

    /**
     * 将扁平菜单列表组装为树形结构（通用方法）
     */
    private List<SysMenu> buildTree(List<SysMenu> menuList) {
        return menuList.stream()
                .filter(m -> m.getParentId() == 0)      // 找顶级节点
                .sorted(Comparator.comparingInt(SysMenu::getOrderNum))
                .peek(m -> m.setChildren(getChildren(m, menuList)))
                .collect(Collectors.toList());
    }

    private List<SysMenu> getChildren(SysMenu parent, List<SysMenu> all) {
        return all.stream()
                .filter(m -> parent.getId().equals(m.getParentId()))
                .sorted(Comparator.comparingInt(SysMenu::getOrderNum))
                .peek(m -> m.setChildren(getChildren(m, all)))
                .collect(Collectors.toList());
    }
}
```

## 7. 步骤四：创建菜单 Controller

### 7.1 SysMenuController.java

文件路径：`bz_framework_core/src/main/java/com/linan/system/controller/SysMenuController.java`

```java
package com.linan.system.controller;

import com.linan.core.common.api.Result;
import com.linan.core.common.controller.BaseController;
import com.linan.core.security.interceptor.AuthInterceptor;
import com.linan.system.entity.SysMenu;
import com.linan.system.service.ISysMenuService;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.*;

import java.util.List;

/**
 * 菜单 Controller
 *
 * 自动继承 BaseController 的通用 CRUD 接口：
 * - GET /api/system/v1/menus/list         分页查询（一般不用，菜单用树形接口）
 * - GET /api/system/v1/menus/{id}         根据ID查询
 * - POST /api/system/v1/menus             新增菜单
 * - PUT /api/system/v1/menus              更新菜单
 * - DELETE /api/system/v1/menus/{id}      删除菜单
 *
 * 额外提供：
 * - GET /menus/routers    获取当前用户的动态路由菜单
 * - GET /menus/treeselect 获取菜单树（用于菜单管理页面的下拉树选择）
 */
@RestController
@RequestMapping("/api/system/v1/menus")
public class SysMenuController extends BaseController<SysMenu, ISysMenuService> {

    @Autowired
    private ISysMenuService menuService;

    @Override
    protected ISysMenuService getService() {
        return menuService;
    }

    /**
     * 获取当前用户的路由菜单（用于前端动态路由）
     *
     * GET /api/system/v1/menus/routers
     *
     * 需要 Token 认证（AuthInterceptor 自动处理）
     * 不需要权限注解（每个登录用户都应该能获取自己的菜单）
     *
     * 返回：树形结构的菜单列表
     */
    @GetMapping("/routers")
    public Result<List<SysMenu>> getRouters() {
        // 从 AuthInterceptor 的 ThreadLocal 中获取当前用户ID
        Long userId = AuthInterceptor.getCurrentUserId();
        // 根据用户ID查询并构建菜单树
        List<SysMenu> menuTree = menuService.buildMenuTreeByUserId(userId);
        return Result.success(menuTree);
    }

    /**
     * 获取菜单树（用于菜单管理页面，返回所有菜单的树形结构）
     *
     * GET /api/system/v1/menus/treeselect
     *
     * 返回所有未删除的菜单（不论状态），方便管理员管理
     */
    @GetMapping("/treeselect")
    public Result<List<SysMenu>> treeselect() {
        // 查询所有菜单（M + C 类型）
        List<SysMenu> allMenus = menuService.list();
        // 组装树形结构
        List<SysMenu> tree = buildTree(allMenus);
        return Result.success(tree);
    }

    // 复用 buildTree 方法（与 Service 中逻辑相同）
    private List<SysMenu> buildTree(List<SysMenu> list) {
        return list.stream()
                .filter(m -> m.getParentId() == 0)
                .peek(m -> m.setChildren(getChildren(m, list)))
                .collect(Collectors.toList());
    }
    // ...
}
```

## 10. 常见问题

**Q: 删除一个菜单后，其子菜单会怎样？**

A: 在 Service 层需要添加校验逻辑：如果菜单有子菜单（`SELECT COUNT(*) FROM sys_menu WHERE parent_id = #{menuId}` > 0），则不允许删除。同样，如果菜单被某个角色引用，也需要先删除关联关系。

**Q: 为什么 getRouters 返回的是树形结构而非扁平列表？**

A: 前端 Element Plus 的 el-menu 组件需要树形结构数据。如果后端返回扁平列表，前端需要遍历所有菜单，根据 parentId 自行构建父子关系。将组装逻辑放在后端，可以保证前后端数据结构的一致性，同时减少前端计算量。

**Q: 菜单的 perms 字段和 @RequirePermission 注解是什么关系？**

A: perms 是数据库中定义权限标识的字段，@RequirePermission 是后端 AOP 拦截时读取的注解。前端请求一个接口时：
1. 前端通过 `v-permission` 指令检查用户是否有对应 perms，无权限则隐藏按钮
2. 即使前端被绕过（手动发送 HTTP 请求），后端 AOP 切面也会读取 `@RequirePermission` 注解中的值，与用户拥有的 perms 列表比对，无权限返回 403

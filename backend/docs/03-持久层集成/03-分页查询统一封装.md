# 03-分页查询统一封装

## 1. 概述

本章创建分页查询的统一封装 `PageResult<T>`，将对标若依框架中分页返回体的标准化格式。虽然 MyBatis-Plus 提供了 `IPage<T>` 接口，但直接暴露给前端存在两个问题：

1. 字段名不一致：`IPage.getCurrent()` 返回当前页，但字段名 `current` 对前端不友好
2. 暴露内部类：前端不应该依赖 MyBatis-Plus 的类结构

`PageResult` 将分页数据封装为标准字段（total、pageNum、pageSize、pages、list），与接口规范中的分页格式完全一致。

**本章新建文件**：

| 文件路径 | 说明 |
| :--- | :--- |
| `bz_framework_core/.../common/api/PageResult.java` | 统一分页返回体 |

---

## 2. 前端分页格式约定

回顾接口规范中定义的分页响应格式：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "total": 100,
    "pageNum": 1,
    "pageSize": 20,
    "pages": 5,
    "list": [
      { "userId": 1, "userName": "admin" }
    ]
  }
}
```

Element Plus 的 `el-pagination` 组件需要的字段正是 `total`、`pageNum`、`pageSize`。

## 3. 代码实现

### 3.1 PageResult.java

文件路径：`bz_framework_core/src/main/java/com/linan/core/common/api/PageResult.java`

```java
package com.linan.core.common.api;

import com.baomidou.mybatisplus.core.metadata.IPage;
import lombok.Data;

import java.util.List;

/**
 * 统一分页返回体
 *
 * 用于包装 MyBatis-Plus 的 IPage 分页结果，
 * 返回给前端一个标准化的分页 JSON 结构。
 *
 * 相比直接返回 IPage，PageResult 有以下好处：
 * 1. 字段名与前端约定完全一致（total/pageNum/pageSize/pages/list）
 * 2. 避免暴露 MyBatis-Plus 内部类给前端
 * 3. 可以灵活扩展字段（如 summary 汇总信息）
 *
 * @param <T> 列表中的数据类型
 */
@Data
public class PageResult<T> {

    /** 总记录数 */
    private long total;

    /** 当前页码 */
    private long pageNum;

    /** 每页显示条数 */
    private long pageSize;

    /** 总页数：(total + pageSize - 1) / pageSize */
    private long pages;

    /** 当前页的数据列表 */
    private List<T> list;

    /**
     * 从 MyBatis-Plus 的 IPage 对象构建 PageResult
     *
     * IPage 接口中有 4 个方法需要关注：
     * - getTotal()    总记录数
     * - getCurrent()  当前页码
     * - getSize()     每页条数
     * - getPages()    总页数
     * - getRecords()  当前页数据列表
     *
     * @param page MyBatis-Plus 分页查询结果
     * @param <T>  数据类型
     * @return PageResult 实例
     */
    public static <T> PageResult<T> from(IPage<T> page) {
        PageResult<T> result = new PageResult<>();
        result.setTotal(page.getTotal());          // 总记录数
        result.setPageNum(page.getCurrent());      // 当前页码（IPage.getCurrent()）
        result.setPageSize(page.getSize());        // 每页条数（IPage.getSize()）
        result.setPages(page.getPages());          // 总页数（IPage.getPages()）
        result.setList(page.getRecords());         // 当前页数据（IPage.getRecords()）
        return result;
    }
}
```

**逐行讲解**：

- `public class PageResult<T>`：泛型参数 T 表示列表中数据的类型。如 `PageResult<User>` 表示返回的是用户列表分页。

- `static <T> PageResult<T> from(IPage<T> page)`：静态工厂方法。接收 MyBatis-Plus 的 IPage 对象，转换为 PageResult。

- `page.getCurrent()`：MyBatis-Plus 返回的当前页码字段。从这里取出后映射为我们约定的 `pageNum` 字段名。

- `page.getRecords()`：当前页的数据列表。直接赋值给 `list` 字段。

## 4. 使用方式

### 4.1 在 Controller 中使用

```java
@RestController
@RequestMapping("/api/system/v1/users")
public class UserController extends BaseController<SysUser, UserService> {

    @Override
    protected UserService getService() {
        return userService;
    }

    /**
     * 自定义分页查询（带搜索条件）
     * GET /api/system/v1/users?pageNum=1&pageSize=10&userName=admin
     */
    @GetMapping
    public Result<PageResult<SysUser>> search(
            @RequestParam(defaultValue = "1") Integer pageNum,
            @RequestParam(defaultValue = "10") Integer pageSize,
            @RequestParam(required = false) String userName) {

        // 1. 创建分页对象
        Page<SysUser> page = new Page<>(pageNum, pageSize);

        // 2. 构建查询条件
        QueryWrapper<SysUser> wrapper = new QueryWrapper<>();
        if (userName != null && !userName.isEmpty()) {
            wrapper.like("user_name", userName);
        }

        // 3. 执行分页查询
        IPage<SysUser> iPage = userService.page(page, wrapper);

        // 4. 转换为 PageResult 返回
        return Result.success(PageResult.from(iPage));
    }
}
```

### 4.2 生成的 SQL

MyBatis-Plus 在分页查询时会生成两条 SQL：

```sql
-- 1. 先查询总记录数
SELECT COUNT(*) FROM sys_user WHERE del_flag = 0 AND user_name LIKE '%admin%';

-- 2. 再查询当前页数据
SELECT * FROM sys_user WHERE del_flag = 0 AND user_name LIKE '%admin%' LIMIT 0, 10;
```

查询总记录数是分页的必要步骤，不能省略。如果数据量极大（千万级），可以考虑使用 Elasticsearch 等搜索引擎替代 COUNT 查询。

# 03-权限插件与业务集成手册

本手册介绍如何在 BareZen_OA 项目中扩展权限功能，以及在 `bz_web_app` 中进行业务开发。

## 1. RBAC 权限模型设计
BareZen_OA 采用经典的五表结构实现权限控制，表之间通过逻辑关联而非物理外键。

### 核心数据表
| 表名 | 说明 |
| :--- | :--- |
| `sys_user` | 用户基础信息 |
| `sys_role` | 角色定义（如：管理员、普通用户） |
| `sys_menu` | 菜单与按钮权限标识 |
| `sys_user_role` | 用户与角色的关联 |
| `sys_role_menu` | 角色与权限的关联 |

## 2. 细粒度接口鉴权 (AOP)
我们利用 Spring AOP 实现方法级别的权限校验。

### 使用 `@RequirePermission`
在 Controller 方法上添加注解，即可限制访问：
```java
@RequirePermission("system:user:delete")
@DeleteMapping("/{id}")
public Result<Void> deleteUser(@PathVariable Long id) {
    // 业务逻辑
}
```

## 3. 业务模块开发 (`bz_web_app`)
`bz_web_app` 是项目的启动入口，负责整合所有模块。

### 依赖管理
在 `bz_web_app/build.gradle.kts` 中引入核心模块：
```kotlin
dependencies {
    implementation(project(":bz_framework_core"))
    // implementation(project(":framework-rbac")) // 需要时开启
}
```

### 配置文件
在 `resources/application.yml` 中配置：
- **DataSource**: 连接本地 Docker 启动的 MySQL。
- **Redis**: 缓存 Token 和权限信息。
- **JWT**: 设置密钥和过期时间。

## 4. 学习路线建议
1. **入门**: 先跑通 `bz_framework_core` 的 Hello World 接口。
2. **进阶**: 尝试手动编写一个 JWT 拦截器并测试登录流程。
3. **实战**: 结合前端 `frontend-admin`，完成一个完整的“用户管理”增删改查功能。

# 02-防重复提交

## 1. 功能概述

防重复提交防止用户因网络延迟、误操作等原因重复提交表单。典型场景：用户在新增订单时，连续点击了两次"提交"按钮，导致数据库中出现两条相同的订单记录。

**常见重复提交场景**：

| 场景 | 原因 | 后果 |
| :--- | :--- | :--- |
| 连续点击 | 用户手快或网络慢，重复点击提交按钮 | 生成两条相同订单 |
| 表单重复提交 | 浏览器后退后又提交 | 重复扣款/创建数据 |
| 恶意脚本 | 攻击者用脚本高频提交 | 数据库被垃圾数据填满 |
| 网络超时重试 | 前端超时自动重试 | 虽然前一次已成功，仍再次执行 |

**解决方案逻辑**：

```
请求到达 Controller 前：
  -> 生成请求指纹（用户ID + 请求路径 + 请求体MD5）
  -> 检查 Redis 中是否存在此指纹的锁（setIfAbsent）
     -> 存在：重复提交，拒绝（返回"请勿重复提交"）
     -> 不存在：存入 Redis，设置过期时间（如 3 秒），放行
```

---

## 2. 防重复提交 vs 接口限流

| 特性 | 防重复提交 | 接口限流 |
| :--- | :--- | :--- |
| 目的 | 防止**相同内容**的请求重复提交 | 防止**请求频率过高** |
| 判断依据 | 请求内容（body）是否相同 | 请求次数是否超阈值 |
| 典型场景 | 新增订单、修改配置 | 登录接口、短信接口 |
| 时间窗口 | 短（1-5 秒） | 较长（60 秒） |
| 实现方式 | MD5(用户ID+路径+请求体) + SETNX | IP+路径 计数器 |

## 4. @RepeatSubmit 注解

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface RepeatSubmit {
    /** 锁定时间（秒），默认 3 秒 */
    int interval() default 3;
}
```

## 5. RepeatSubmitAspect 核心实现

```java
@Aspect
@Component
public class RepeatSubmitAspect {

    @Autowired
    private RedisTemplate<String, Object> redisTemplate;

    private static final String REPEAT_SUBMIT_PREFIX = "repeat_submit:";

    @Around("@annotation(RepeatSubmit)")
    public Object around(ProceedingJoinPoint joinPoint) throws Throwable {
        MethodSignature signature = (MethodSignature) joinPoint.getSignature();
        RepeatSubmit repeatSubmit = signature.getMethod().getAnnotation(RepeatSubmit.class);

        Long userId = AuthInterceptor.getCurrentUserId();
        if (userId == null) {
            return joinPoint.proceed();  // 未登录用户不需要防重复
        }

        // 生成请求指纹：MD5(用户ID + URL + 请求体)
        String fingerprint = generateFingerprint(userId, joinPoint.getArgs());
        String key = REPEAT_SUBMIT_PREFIX + fingerprint;

        // setIfAbsent = SETNX，原子操作
        // 成功获取锁 → 第一次请求，放行
        // 获取失败 → 重复提交，拒绝
        Boolean acquired = redisTemplate.opsForValue()
                .setIfAbsent(key, "1", repeatSubmit.interval(), TimeUnit.SECONDS);

        if (Boolean.TRUE.equals(acquired)) {
            return joinPoint.proceed();
        } else {
            return Result.error("请勿重复提交");
        }
    }

    private String generateFingerprint(Long userId, Object[] args) {
        StringBuilder sb = new StringBuilder();
        sb.append(userId).append(":");
        for (Object arg : args) {
            if (arg != null && !(arg instanceof MultipartFile)) {
                sb.append(arg.toString());
            }
        }
        return DigestUtils.md5DigestAsHex(sb.toString().getBytes(UTF_8));
    }
}
```

**为什么用 SETNX 而不是普通的 SET？**

SETNX = SET if Not eXists，原子性地"检查 key 是否存在，不存在则设置"。如果两个请求同时到达，Redis 保证只有一个请求能获取到锁。

## 6. 使用示例

### 防止重复新增用户

```java
@RepeatSubmit(interval = 3)  // 3秒内相同请求视为重复
@PostMapping
public Result<Void> save(@RequestBody SysUser user) {
    // 用户连续点击两次"提交"按钮，第二次会被拦截
}
```

### 防止重复创建订单

```java
@RepeatSubmit(interval = 5)  // 订单场景更敏感，设 5 秒
@PostMapping("/order/create")
public Result<Void> createOrder(@RequestBody Order order) {
    // ...
}
```

## 7. 前后端双重防护

```vue
<el-button type="primary" :loading="submitting" @click="handleSubmit">
  {{ submitting ? '提交中...' : '确认提交' }}
</el-button>

<script setup>
const submitting = ref(false)
const handleSubmit = async () => {
  submitting.value = true
  try {
    await save(formData)
    ElMessage.success('操作成功')
  } catch (e) {
    ElMessage.error(e.message)
  } finally {
    submitting.value = false
  }
}
</script>
```

1. **前端**：提交后禁用按钮，防止 UI 层面的重复点击
2. **后端**：AOP 切面 + Redis，防止绕过前端的恶意请求
